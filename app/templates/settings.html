1 · Add a proxy node

Create the smallest Ubuntu 24.04 VM with a public IPv4 at any provider, open TCP {{ s.node_http_port }} in the provider's firewall, then run this on it. It installs Squid (HTTP/HTTPS proxy on port {{ s.node_http_port }}) with its own username and password, and registers itself here — it shows up as 🆗 Ready within a minute. Change --provider and --region per node.

curl -fsSL{{ 'k' if insecure }} {{ base }}/install-node.sh | sudo bash -s -- \
  --main {{ base }} \
  --token {{ s.enroll_token or 'SET_ENROLL_TOKEN' }} \
  --provider digitalocean --country US --region nyc1{{ ' --insecure' if insecure }}

Add --socks to also run a SOCKS5 proxy on {{ s.node_socks_port }}. Don't run this on the existing GCP Squids that apps already use — it would change their password. Add those on the Add or Apps page instead.

3 · API (optional)

Not needed for daily work — it's there for scripts. Send the key in the X-API-Key header.

# the proxy currently assigned to one app (plain URL)
curl -H "X-API-Key: $KEY" "{{ base }}/api/v1/apps/APP_NAME/proxy?format=url"

# every app and its proxy
curl -H "X-API-Key: $KEY" {{ base }}/api/v1/apps

# Ready + healthy proxies (free to pick)
curl -H "X-API-Key: $KEY" "{{ base }}/api/v1/proxies?free=1&format=url"

# tell us a proxy failed (logged + rechecked immediately)
curl -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
  -d '{"host":"1.2.3.4","port":3128,"source":"APP_NAME","error":"timeout"}' {{ base }}/api/v1/report
